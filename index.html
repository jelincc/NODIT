※ 목업의 사이드바·헤더 크롬은 실제 Nodit Console 화면을 참고해 재현했으며, 개선 제안은 메인 콘텐츠 영역(요약 스트립 · Getting Started · Project · Usage Detail · 우측 레일)에 한정됩니다. 색상은 Nodit 브랜드 그린을 액센트로 유지하고, 본문은 시스템 UI 폰트, 수치 데이터는 tabular-nums 모노스페이스로 구분해 가독성을 높였습니다.

디자인 설명

문제 · 가설 · 검증 · 임팩트

결과 화면뿐 아니라 문제를 해결하는 과정을 함께 보여드리기 위해, 발견한 문제마다 근거 → 가설 → 가설을 증명하기 위한 검증 조건 → 기대 임팩트 순으로 정리했습니다.

근본 문제: Overview 화면의 정보 위계가 "운영 대시보드"가 아니라 "마케팅 랜딩페이지"에 가깝습니다. 유저가 로그인하는 목적(내 프로젝트·사용량 확인)과 화면이 가장 먼저 보여주는 것 (제3자 상품 광고, 업그레이드 세일즈)이 어긋나 있고, 아래 4가지 문제는 이 root cause에서 파생됩니다.

01프로모션 배너가 정보 위계를 압도

문제 · 근거

1440×900 기준 최초 뷰포트에서 프로모션성 콘텐츠(Solana 배너 + Dedicated 업그레이드 배너)가 차지하는 세로 영역이 약 260px/900px(≈29%). 실제 유저 데이터(프로젝트 테이블, 사용량)는 이 아래, 스크롤해야 등장합니다.

Nielsen Norman Group의 배너 블라인드니스(F-pattern 시선추적) 연구에 따르면, 반복적으로 배너 형태·위치에 노출된 유저는 해당 영역을 스캔에서 자동 제외하도록 학습됩니다 — 광고 효과와 UX를 동시에 잃는 구조입니다.

가설

실사용 데이터를 최상단, 프로모션을 보조 위치로 재배치하면 (a) 핵심 정보 인지 속도가 빨라지고 (b) 배너 참여율은 하락하지 않거나 오히려 상승한다(블라인드니스 해소).

가설 검증 조건 · 데이터 근거
  • 선행 조건 — 배너 CTA 클릭 이벤트 트래킹 추가(현재 미보유 가정)
  • 실험 설계 — 신규 가입 유저 대상 기존안(A) vs 개선안(B) 50:50 A/B, 최소 2주 수집
  • 1차 지표 — 진입 5초 내 프로젝트/사용량 영역 도달률(세션 리플레이) — B가 A 대비 15%p↑ 필요
  • 가드레일 — 배너 CTR이 20% 이상 하락하면 가설 기각
기대 임팩트

핵심 화면 인지 시간 단축 → 온보딩 완료율 상승. 배너 CTR 유지·상승 시 마케팅 성과 지표도 개선.

02핵심 정보가 스크롤 없이 확인 불가

문제 · 근거

원본 화면 기준 Usage Overview·My Plan 섹션 도달까지 스크롤 약 3회 필요. 콘솔 로그인의 최빈 목적(오늘 사용량/한도 확인)이 화면에서 가장 늦게 등장하는 역설적 구조입니다.

가설

상단에 4개 핵심 스탯(플랜·CU 사용량·요청수·프로젝트 수) 요약 스트립을 배치하면 정보 탐색 시간이 단축되고 세션당 재방문 빈도가 늘어난다.

가설 검증 조건 · 데이터 근거
  • 선행 조건 — 세션 단위 스크롤 뎁스 트래킹 필요(현재 미보유 가정)
  • 실험 설계 — 기존 유저 코호트 대상 개선 전/후 비교(within-subject)
  • 지표 — Time-to-Info(로그인~핵심 지표 확인 시간), Overview 재방문 빈도(WAU/MAU)
  • 성공 기준 — Time-to-Info 50%↑ 단축, 4주 후 WAU/MAU 5%p↑
기대 임팩트

API 한도를 자주 체크하는 파워 유저의 재방문 만족도·세션 효율 개선.

03빈 데이터 상태에 액션 유도 부재

문제 · 근거

신규 유저는 항상 0 데이터로 시작(By Projects/By APIs/CU 전부 0). 프로젝트 생성일 (2025-10-30)은 있는데 요청은 0건 — 가입은 했지만 활성화(Activation)로 전환되지 못한 상태입니다. 현재 화면은 이를 의미 없는 평평한 그래프로만 보여줄 뿐 다음 행동을 알려주지 않습니다.

가설

빈 상태를 액션 유도형 "Getting Started" 체크리스트로 대체하면 신규 유저의 활성화율 (첫 API 호출 도달률)이 상승한다.

가설 검증 조건 · 데이터 근거
  • 선행 조건 — 가입~첫 호출 Funnel 이벤트(가입→프로젝트 생성→키 발급→첫 호출) 정의·로깅
  • 실험 설계 — 가입 주차 기준 코호트 비교(최소 4주) 또는 트래픽 충분 시 A/B 병행
  • 지표 — Activation Rate(가입 후 7일 내 첫 호출 도달률), Time to First Value
  • 근거 — Slack·Linear 등 B2B SaaS의 체크리스트형 온보딩이 Activation Rate를 개선한 사례 다수 — 유사 패턴으로 채택, Nodit 자체 데이터 재검증 필요
  • 성공 기준 — Activation Rate 10%p↑
기대 임팩트

Time to First Value 단축, 활성화 유저의 무료→유료 전환 가능성 제고.

04업그레이드 CTA가 3곳에 분산

문제 · 근거

"See Plans"(헤더), "Contact Us"(Dedicated 배너), "Upgrade"(My Plan) — 동일 의도(더 많은 리소스 필요)의 CTA가 서로 다른 위치·문구로 3개 존재합니다. 전환 의도가 3갈래로 쪼개져 있어 단일 퍼널로 분석이 불가능한 구조 자체가 문제입니다.

가설

목적별 CTA를 1곳으로 통합(Dedicated 문의=텍스트 링크, Plan 업그레이드=My Plan 카드 버튼) 하면 전환 경로가 명확해져 클릭→전환율이 상승한다.

가설 검증 조건 · 데이터 근거
  • 선행 조건 — CTA별 클릭 + 다운스트림 전환(폼 제출, Upgrade 완료) 연결 트래킹
  • 실험 설계 — A/B(트래픽 충분 시) 또는 전/후 비교, "클릭→전환" 퍼널 드롭오프율 비교
  • 지표 — Click-to-Conversion Rate(CTR보다 클릭 대비 실전환율에 집중)
  • 성공 기준 — 통합 후 전환율이 기존 3개 CTA 평균 대비 상승
기대 임팩트

Sales 리드 품질 상승, 단일 CTA 지점 확보로 이후 지속적인 A/B 테스트 가능.

솔루션 비교

가장 영향이 큰 두 가지 의사결정은 복수 안을 검토한 뒤 골랐습니다.

A. 빈 데이터 상태 처리장점단점
① Getting Started 체크리스트 다음 액션이 구체적, 진행률(1/4) 시각화로 동기부여, 기존 데이터로 상태 판단 가능해 구현 난이도 낮음 활성화 완료 후 숨김 처리 로직 필요
② 단순 Empty State 구현 가장 간단 수동적 정보 전달에 그침, 위젯 여러 개가 동시에 비면 페이지가 허전해 보임
③ 데모/프리뷰 데이터 데이터가 쌓였을 때의 모습을 미리 보여줌 "가짜 데이터"임을 명확히 표기 안 하면 실데이터로 오인 위험 — 온체인 데이터 특성상 신뢰 이슈로 치명적
B. 프로모션 배너 위치장점단점
① 우측 보조 레일로 축소 노출은 유지하면서 위계는 부차적으로 조정 — 비즈니스 요구와 유저 경험 절충 여전히 일부 공간 차지
② 완전 제거 가장 깔끔한 데이터 중심 화면 신규 상품 홍보 니즈 미충족 — 실무에서 반려 가능성 높음
③ 별도 Discover 페이지 분리 Overview를 순수 상태 대시보드로 완전 분리, 확장성 좋음 IA 변경 필요 — 이번 과제 범위(Overview 화면)를 벗어남
